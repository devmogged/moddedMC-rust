# WS-4: Create addons (P5)

Branch: `ws/create-addons`. Survey date: 2026-11-20. The target server is Java 26.3; versions below are the **mod's own latest available releases**, even when built for another Minecraft version. Work in a separate `.mmc` crate for each addon. The Create host is provided by `mods/create`, and WS-0 owns the shared ABI and inter-mod services.

### Source study and exact hooks

Six published source repositories were checked out separately under `D:/mc-ref/*-latest`. These are current source snapshots rather than independently verified tags corresponding to every listed release. Their revisions are: New Age `57f66eb`; Crafts & Additions `007a0ed`; Enchantment Industry `7cb2e9f` (2.5.4b NeoForge); Central Kitchen `9ba56a9`; Steam 'n' Rails `7441960c`; Create More Recipes branch `1.21.1` `79cc098`. Match method bodies with the correct released jar before implementing gameplay logic.

- **Crafts & Additions:** `com.mrh0.createaddition.blocks.electric_motor.ElectricMotorBlockEntity` extends `GeneratingKineticBlockEntity`. Its `getGeneratedSpeed()` returns zero when inactive and otherwise uses `convertToDirection(motorSpeed, FACING)`; `tick()` checks available energy, consumes energy and calls `updateGeneratedRotation()` on activation changes. `getEnergyConsumptionRate(float)` depends on absolute RPM. `AlternatorBlockEntity.calculateStressApplied()`, `tick()`, `getEnergyProductionRate(int)` translate Create rotation to stored electricity. `RollingMillBlockEntity.tick()`, `process()`, `find(...)` and its item handler need Create processing and recipe access. Follow energy storage NBT in `read`/`writeSafe`.
- **New Age:** `org.antarcticgardens.cna.content.electricity.generation.coil.GeneratorCoilBlockEntity.calculateStressApplied()`, `tick()` and `takeGeneratedEnergy()` use Create speed/stress and electricity. `ElectricalNetwork.addNode()`, `removeConnection()`, `updateConsumersAndSources()`, `insert(..., TransactionContext)`, `destroy()` and `tick()` manage a separate electrical graph. `ElectricalConnectorBlockEntity.setNetwork()` binds the graph to world blocks. `CNARecipeTypes` includes custom energising, requiring its own serializer/processor.
- **Enchantment Industry:** the 2.5.4b source includes `common.processing.enchanter.BlazeEnchanterBlockEntity.tick()`, `updateEnchanterIfLevelReady()`, `insertItem()`, `extractItem()`, `read()` and `write()`; `common.fluids.printer.PrinterBlockEntity.onItemEnters()`, `onItemHeld()`, `tick()`, `read()`, `write()` act on Create transported item stacks and fluids. Check all changed loaders/mixins in the latest 2.5.4 Fabric jar before implementation.
- **Central Kitchen:** `common.packager.RecipeUnpacking` implements layout matching through `aggregate()`, `orderPattern()`, `multiplier()` and `assign()`; `integration.farmersdelight.mechanicalArm.CookingPotArmInteractionPoint` and `CuttingBoardDeployerRecipe` bridge Farmer's Delight inventory/cooking to Create. `mixin.create.BeltHelperMixin`, `mixin.create.client.BlazeBurnerBlockEntityMixin`, and Farmer's Delight cooking pot/skillet integration are not replicated by installing data files.
- **Steam 'n' Rails:** `com.railwayteam.railways.api.bogeymenu.v0.BogeyMenuManager`, railway `RailwaysSequencedAssemblyRecipeGen`, `RailwaysItemApplicationRecipeGen`, and track/bogey code depend on Create's train graph, bogey and schedule internals. Detailed call-chain study is deferred until WS-3 trains expose their interfaces.
- **More Recipes:** the release's [`1.21.1` source branch](https://github.com/iglee42/create-more-recipes/tree/1.21.1) at `79cc098` confirms that `HeatConditionMixin` adds `cooled` and `frozen`, and `BasinRecipeMixin.cmr$checkForCooler` rejects a cooled/frozen recipe without a snowman cooler directly below the basin at the required heat. The cooler's `tick()`, `tryUpdateFuel()` and `applyCreativeFuel()` manage normal, special and creative fuel; these are required for the vanilla-item ice recipes to work. Packaged classes `fr.iglee42.cmr.autosmithing.SmithingPressBlockEntity`, `blockspout.BlockSpoutBlockEntity`, `cooler.SnowmanCoolerBlockEntity` and mixins `AirCurrentMixin`, `BasinRecipeMixin`, `HeatConditionMixin` prove a recipe-only treatment would lose mechanics. Its nine JSONs include `cmr:mixing/blue_ice`, `packed_ice`, `frozen_cake`, `cmr:compacting/frozen_cake` and `cmr:block_spouting/grass_block`.
- **Other archive-only checks:** Ultimate Factory includes `create_ultimate_factory.event.LivingEntityEvents`; Copper & Zinc has only six processing recipes; Recycle has its three shard/fluff item classes plus the crushing data. No source-level behavioral claims are made for the ARR mods.

### Service contract requested from WS-0 M2

**Create inter-mod service first, not server-specific Rust imports.** An addon must request a named, versioned C table from `create.mmc`, then keep its own energy network and gameplay logic in its own crate. Propose these operations to WS-0 for the first `create:kinetics` v1 table (precise C signatures to be agreed with the Create owner):

| Operation | Evidence / caller | Required behavior |
| --- | --- | --- |
| Register a kinetic generator at a block and set its signed generated speed | Electric motor `getGeneratedSpeed`, `updateGeneratedRotation` | Trigger Create network propagation and stress recalculation; zero output on lost energy |
| Register a kinetic consumer and read speed at its block | Alternator `calculateStressApplied`, New Age coil `calculateStressApplied` | Preserve Create axis/sign, unloaded handling and overstress transitions |
| Read actual and theoretical speed, capacity and stress impact | Alternator/electric motor, generator coil | Distinguish stalled from running networks; no private access to `KineticNetwork` |
| Register processing recipe types and query/execute them against datapack resources | Rolling mill; `cmr` block spout/smithing press; New Age energising | Must preserve recipe order, reload generation, item inputs and outputs, including residual items |
| Publish/require fluid handlers and insert/extract fluid stacks | Enchantment printer and its experience/ink fluids, New Age integrations | Coordinate with WS-2's fluid work; no mod importing Create's Rust types |
| Named item transport hooks for belts, depots, and spouts | Enchantment printer `onItemEnters`/`onItemHeld`, Central Kitchen | Treat transport events and inventory ordering as original Create does |
| Extension point for train graph/bogeys/schedules | Steam 'n' Rails | Defer until WS-3 publishes train services |

The first three rows are the narrow `create:kinetics` v1 boundary planned in WS-0 M2. Other rows should become separate named/versioned Create service tables as their owners implement those subsystems. Do not add methods to the generic host ABI merely because the addon needs Create-specific behavior. **WS-0 coordination is pending**; no service interface exists yet in the local ABI snapshot, and no M2 addon is runnable.

### M1 order and acceptance tests

1. **More Recipes:** the `mixing/packed_ice` and `mixing/blue_ice` vanilla-item recipes still require the snowman cooler in `FREEZING`; `mixing/frozen_cake` requires `COOLING` and new items. A recipe-only `.mmc` is not viable until WS-2 exposes the custom basin heat check. Start by porting and unit-testing the independent cooler fuel state machine, then register the block, its persistence and heat callback. The server scenario must compare exact ingredient/fluid consumption, heat-state gates and outputs with the NeoForge 1.21.1 release. See coordination request `N:/mmc-coord/requests/WS-4-02.md`.
2. **Data portions of New Age and Crafts & Additions:** scope test recipes that produce items Create already registers. New item/block outputs wait for corresponding content registration; custom rolling/charging/energising are **not** generic Create recipes.
3. **Recycle and Copper & Zinc:** keep original data in ignored jars and record selected recipe ingredients/outputs for testing; copying ARR data or implementing ARR code for a public branch requires a rights review. Reconstructing mechanics from independently established public facts is a separate decision, not permission to copy the files.
4. **Steam 'n' Rails** waits for WS-3. Central Kitchen requires Farmer's Delight compatibility and Create transport hooks. Enchantment Industry has a newer beta than stable release, so implement against the beta's actual method bodies, checking its platform differences.

The root ABI currently loads each `.mmc`'s `data/` as a built-in datapack, but datapack ingestion alone does **not** prove Create supports every recipe type. The current Create implementation has pressing; mixer and crushing-wheel behavior is still under the other workstreams. WS-0 published shared engine test binaries at `N:/mmc-shared/bin/d6e5e8d560/`; M1 processing tests still need WS-2's mixer and the inter-mod heat extension. Later milestones must run targeted `cargo fmt`, `cargo clippy`, `cargo test`, a player-visible bot scenario (including persistence where applicable), and exact original-mod outcome comparison. The survey alone does not prove parity, runtime compatibility or a benchmark improvement. The implemented and tested Create More Recipes subset is recorded separately below.

### M2 preparation: New Age generator coil (logic only)

- Source: New Age `1.2.0+mc1.21.1` NeoForge release, public 1.21.1 source `GeneratorCoilBlockEntity`, `RelativeBlockPos` and `ServerConfig` at `57f66eb`. The generator `tick()` bytecode was cross-checked using `javap -c -p` directly on the released jar, including the float multiplication before applying the double `suToEnergy` conversion.
- Independent `mods/create-new-age/src/generator_coil.rs` models the twelve magnet offsets around X/Y/Z shafts, sum of applicable magnet strength plus plain Create stress, energy generation from stress delta and signed RPM, and the one-time `takeGeneratedEnergy` buffer. Config parameters are passed in rather than hardcoded in the port.
- Additional `src/electrical_network.rs` ports `NetworkPathManager` and `NetworkPathConductivityContext` with depth-limited shortest-path BFS, per-edge conductivity saturation/refill, no longer-path fallback, consumer sharing and cached path invalidation. Four regressions cover the original Java edge cases, plus a 2,000-node cold-path topology regression. The Rust BFS now reconstructs from a parent map once, matching Java's `QueueElement` structure instead of cloning a path for each BFS expansion. One debug-build cold-path measurement on the same laptop improved 7,690 µs → 2,793 µs (single samples; **not** a controlled performance benchmark). Its pure caller supplies receiver capacity, not the full external handler API; exact equal-depth tie ordering and original mod integration remain unverified.
- New `src/energy_storage.rs` models `SimpleNetworkEnergyStorage`: 64-bit capacity/FE, disabled input/output, max per-operation transfer, internal bypass, simulation, capacity clamping and snapshot/restore. Five tests include a cross-module network conductivity/energy-conservation check. Caller-side transaction rollback, final-commit hooks, external energy handlers and world connector behavior remain to be integrated.
- `cargo test -p create-new-age` passed 13/13 and `cargo clippy -p create-new-age --all-targets -- -D warnings` passed. This is **only an `rlib`**, not an installable mod; world-level tag/magnet detection, energy transactions and network propagation need `WS-4-01` kinetics and `WS-4-05` generic energy services. No original-mod runtime parity is claimed.
