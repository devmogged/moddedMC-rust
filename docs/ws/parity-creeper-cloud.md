# WS-7 Creeper lingering-cloud parity slice

Scope: `engine/pumpkin/crates/pumpkin-core/src/entity/mob/creeper.rs` and `tests/harness/mobs/creeper-lingering-cloud.txt`, in the isolated `ws/parity-spawn-empty` worktree. This does not alter the active WS-7 checkout or native-mod ABI.

Java 26.3 oracle: `D:\mc-ref\26.3\src\net\minecraft\world\entity\monster\Creeper.java`, `explodeCreeper` / `spawnLingeringCloud`. When active potion effects are present, creeper explosion creates an `AreaEffectCloud` at its position with radius 2.5, radius-on-use -0.5, wait 10 ticks, duration 300 ticks, radius-per-tick -2.5/300, potion duration scale 0.25, and copies all active potion effects. `PotionContents.forEachEffect` and `MobEffectInstance.withScaledDuration` floor scaled finite durations to at least one tick, leaving infinite/zero durations unchanged. No cloud for an effect-free creeper.

Rust: call `spawn_lingering_cloud` after `world.explode_from` and before `entity.remove()`. Snapshot active effects under a short mutex guard; use existing `AreaEffectCloudEntity::create` with the vanilla values, pre-scaling effect durations because this constructor accepts final effect tuples rather than `PotionContents` with a duration-scale field. Spawn through the world's existing event-aware `spawn_entity`. No new host interface or special-case cloud type.

NBT root cause found in the first post-change differential: `tests/harness/mobs/creeper-lingering-cloud.txt` still reported no cloud even though the direct unit test passed. A diagnostic fixture (`run/creeper-nbt-debug.txt`) found Java serialized `active_effects:[{id:"minecraft:speed",duration:200,...}]` while Pumpkin's `/summon` loaded none. `crates/pumpkin-core/src/entity/effect/mod.rs` used to require `show_icon`, discarding any effect NBT without that field. Java 26.3 `MobEffectInstance.Details.create` defaults missing `show_icon` to the `show_particles` value, which itself defaults true. Rust now does the same; the regression `effect_nbt_defaults_optional_icon_to_particle_visibility` covers missing/default/explicit icon visibility. This is a generic entity-effect-NBT parsing fix, not a creeper-only special case.

RED Java-vs-Rust differential (before fix): `tests/harness/mobs/creeper-lingering-cloud.txt`, real Java 26.3 reference reported `Test passed. Count: 1` for an area-effect cloud after an ignited, effect-bearing creeper exploded, while Pumpkin returned `Test failed` (exactly 1 difference). Report: ignored `run/creeper-cloud-red.json`.

Targeted unit test `creeper_cloud_only_spawns_with_active_effects_and_uses_vanilla_settings`: PASS 1/1 with 816 filtered, verifying absent cloud without effects and a cloud with 300 duration, 10 wait, 2.5 radius, -0.5 radius-on-use, Speed II amplifier and 200 -> 50 finite effect duration. NBT parser unit test `effect_nbt_defaults_optional_icon_to_particle_visibility`: PASS 1/1, 817 filtered, matching Java's `showIcon.orElse(showParticles)`. Full engine pack build `cargo build --manifest-path engine/Cargo.toml --profile pack -p pack-dev -p moddedmc-bot -p moddedmc-harness` PASS; `cargo clippy --manifest-path engine/Cargo.toml --profile pack -p pack-dev --all-targets -- -D warnings` PASS; formatting and diff whitespace checks PASS. The final Java 26.3 differential `tests/harness/mobs/creeper-lingering-cloud.txt` now PASS: **0 differences**, no runtime error, no allowances. It uses a normalized pre-explosion snapshot to compare NBT, avoiding a purely textual key-order mismatch in `/data get` output. Report: ignored `run/creeper-cloud-canonical.json`.

Limits: `AreaEffectCloudEntity::tick` itself has separate vanilla gaps in application cadence, duration-after-wait semantics and horizontal-only radius; pre-scaling the duration is intended for the creeper cloud's effects, not a general substitute for the vanilla duration-scale component. Recheck runtime cloud behavior in a dedicated follow-up. No claim of complete creeper, effect-cloud, AI or server parity.
