# Create: New Age

Partial source-backed port of **Create: New Age `1.2.0+mc1.21.1`** (NeoForge). Original code is BSD-3-Clause (Antarctic Gardens). No original game assets are bundled.

The independent `src/energy_storage.rs` now ports `SimpleNetworkEnergyStorage`: 64-bit stored/capacity values, external per-call input/output limits, internal transfers, simulation, capacity clamping and transaction snapshot restoration. Its original transactional host hooks and final-commit callbacks are not yet connected. One test combines energy-handler acceptance with the network's shared edge conductivity, checking conservation of received FE. The Rust crate currently implements the generator coil's twelve magnet offsets around X, Y and Z shafts, its magnet-dependent stress and FE production, and the consume-once generated-energy buffer. `src/electrical_network.rs` also ports `NetworkPathManager` and `NetworkPathConductivityContext`: parent-pointer shortest-path BFS with configurable depth, edge budgets that reset each tick, no longer-path fallback when saturated, and the consumer distribution loop. Source: `GeneratorCoilBlockEntity`, `RelativeBlockPos`, `ElectricalNetwork` and the path manager classes in the public 1.21.1 source. The generator `tick()` was checked against the published 1.2.0 NeoForge jar. Conversion uses the original configurable `suToEnergy` value, supplied as a parameter.

The native `create-new-age.mmc` now registers ten original plain `CNAItems` items (overcharged gold, iron and diamond; nuclear fuel; thorium and radioactive thorium; both overcharged sheets; blank and copper circuits), plus five source-defined passive magnetic blocks (magnetite, redstone, layered, fluxuated and netherite magnets). Their `ImplementedMagnetBlock` field strengths are 1, 2, 4, 8 and 24, exercised by a coil-stress unit test but **not yet hooked to a live generator**. The original three supported magnet crafting recipes, all five block loot tables and six magnetic/nuclear/mining tags load. Magnetic hardness 5.0/resistance 7.0 is currently approximated with the host's `minecraft:iron_block` physical template; live behavior is not fully parity-exact. These are passive content definitions; reactor and wire behavior are not registered. The release jar supplies art locally through `MODDEDMC_ASSET_JARS`, not public Git. `tests/scenarios/ws4-new-age-items.txt` verifies item IDs, tags and inventory persistence. `ws4-new-age-magnets.txt` verifies all five blocks' mining tags, original loot, recipe unlocks and block persistence. `ws4-new-age-magnet-crafting.txt` verifies actual six-overcharged-iron plus three-overcharged-gold crafting produces four layered magnets and the inventory survives restart.

Build with `powershell -NoProfile -File scripts/pack-mod.ps1 -Crate create-new-age`. Tests: `cargo test -p create-new-age`, `cargo clippy -p create-new-age --all-targets -- -D warnings`.

The crate is packaged as a loadable `.mmc` for its **passive items and passive magnet blocks only**. All generator-coil, energy-network and storage modules remain independently testable logic and are **not yet connected to live gameplay**. The pure network caller supplies each receiver's acceptable capacity, while the original Java network asks the installed energy handler to insert each transfer, so per-call handler constraints and equal-length-path iteration order still need original-mod oracle tests. Full gameplay needs Create's inter-mod kinetic source/consumer service (`WS-4-01`) and registered electrical connectors, magnets, item/block content and persistence. An original Java-mod oracle must verify stress, network power delivery and restart before calling the mechanic ported.
